# media-remux 0.2.0 替换评估

`media-remux@0.2.0` 覆盖扩展的 DASH 音视频合并和独立 AAC 导出，可以替换浏览器直接依赖的 Mediabunny。它也能处理常规 progressive MP4/FLV，但对编码、轨道选择和时间轴有额外限制。完整移除浏览器 FFmpeg 前，需要确认这些限制对 B 站实际返回的旧格式素材有多大影响。Python 助手调用本机 FFmpeg，其运行环境和输出契约需要单独迁移。评估以 `v0.2.0` 标签和扩展当前工作区（HEAD `b4dab0a`）为准。 [GitHub 发布记录](https://github.com/ntnyq/media-remux/releases/tag/v0.2.0) · [npm 发布元数据](https://registry.npmjs.org/media-remux)

## 兼容边界

- `concatMedia` 写入前对比轨道布局、编码配置字节、宽高与色彩、采样率、声道和变换矩阵。每段视频必须以关键帧开头，库按上一段最晚呈现结束点拼接。FFmpeg concat demuxer 按段时长定位下一段，实际切点可能不同。MP4 的多采样描述、部分编辑列表和不连续的 AV1 时间轴也会在预检失败。 [拼接实现](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/core/remux.ts#L53-L159) · [轨道预检](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/core/mediaTracks.ts#L95-L175) · [库的兼容规则](https://github.com/ntnyq/media-remux/blob/v0.2.0/README.zh-CN.md#L364-L384) · [FFmpeg concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat-1)
- 库的 FLV 解析器只接受标准 AVC 视频与 AAC-LC 音频，并拒绝 HE-AAC/SBR、段内序列头变化和不支持的标签。扩展回退到 `durl` 时只检查画质和地址，没有提前验证 progressive 的实际容器和编码，所以无法依据当前选流逻辑断定这些输入从来不会出现。 [FLV 解析器](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/core/input/flvInput.ts#L114-L152) · [FLV AAC 配置](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/core/input/flvInput.ts#L248-L267) · 扩展的 progressive 回退 `utils/bilibili/streams.ts:304`
- 发布包没有运行时依赖。它内置基于 Mediabunny 1.66.2 的 MPL-2.0 源码子集，保留原项目基于 1.62.1 的大文件补丁所实现的分页读取、磁盘样本存储和分片索引写入，并有后续修改。迁移可删除直接安装的 `mediabunny` 及扩展自己的补丁维护，但发布扩展仍需随包保留相应第三方声明。 [源码迁移记录](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/vendor/mediabunny/MIGRATION.md) · [第三方声明](https://github.com/ntnyq/media-remux/blob/v0.2.0/THIRD_PARTY_NOTICES.md)

## 接入与验证

先在现有 `mergeBrowserMedia` / `remux.worker.ts` 生命周期中调用 `combineTracks`、`remuxMedia` 和 `createOpfsStorage`，可以沿用下载缓存、配额预检、错误本地化、120 秒 Worker 启动确认以及保存后释放输出的契约。高层 `runMediaJob` 可代管 Worker 和临时目录，但 0.2.0 的 Worker 没有启动确认这一阶段。若改用高层 API，需要以扩展缓存下的 `merged-output` 作为父目录，保留残留清理与取消行为，并适配其按编码载荷字节而非容器文件大小报告的进度。 扩展 Worker 生命周期 `utils/downloads/media/mergeBrowserMedia.ts:37` · [库的 Worker 客户端](https://github.com/ntnyq/media-remux/blob/v0.2.0/src/browser/client.ts#L122-L322) · [库的进度契约](https://github.com/ntnyq/media-remux/blob/v0.2.0/README.zh-CN.md#L369-L384)

使用通过 SHA-512 校验的 npm 发布包和 Node 定位读写适配器，实测了扩展的 AVC + AAC（含长 GOP 和用 `-movflags +dash+global_sidx` 生成的分离 `.m4s`）、纯 AAC、两段同配置的 FLV 拼接、两段同配置的 MP4 拼接，以及上游 `hvc1`、`hev1`、`av01` 样例分别与扩展 AAC 合并。输出均通过 FFmpeg 解码，`ffprobe` 确认每轨编码包的 SHA-256 及顺序与输入一致。轨道布局不匹配的拼接在开始写出前被拒绝。 扩展测试素材 `tests/fixtures/downloads` · [上游测试素材](https://github.com/ntnyq/media-remux/tree/v0.2.0/tests/fixtures)

旧格式可先保留浏览器 FFmpeg 作为兼容回退。回退需要能区分明确的媒体不兼容与取消、磁盘配额、写入失败等任务错误。判断能否删除这条路径时，应在 Chromium 和 Firefox 用有代表性的 B 站素材覆盖 H.264、HEVC、AV1、独立 AAC，以及单段、多段和无音轨 progressive。对比解码、音画同步和切点，同时验证下载文件后缀、大文件、取消和失败清理。当前扩展加载的 FFmpeg JS 与 WASM 原文件共约 30.85 MiB，只有移除浏览器回退后才能省去这两项构建资源。 现有 progressive 测试 `tests/downloads/ffmpegDiskFile.test.ts:199` · WXT 资源和 manifest `wxt.config.ts:27`
